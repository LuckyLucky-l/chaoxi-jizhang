# 07 · 页面识别（通知漏单补记）

> 通知只覆盖了一部分场景，有些 App 或页面压根不发可解析的支付通知。
> 页面识别是**第二条输入源**：你打开付款 / 账单详情页时，应用读页面文字，认出一笔，弹框让你确认后再记账。
> 设计文档：[docs/superpowers/specs/2026-10-12-页面识别自动记账.md](superpowers/specs/2026-10-12-页面识别自动记账.md)

---

## 1. 定位与边界

- **补漏，不替代通知**：通知仍是第一优先来源（见 §5 冲突优先级）。
- 一次只认**一笔**（交易详情页）；不限微信/支付宝，其他 App 也能读。
- **必须经用户确认才落账**：页面文字是启发式识别的，可能误读，所以默认不自动写。
- 读的是**控件节点文字**（`node.text` / `contentDescription`），不用截屏 OCR、不用剪贴板。

---

## 2. 数据流

```
用户在任意 App 打开账单详情页
   ▼ 无障碍服务收内容变化事件（同页防抖）
BillRecognitionService（取文字 + 识别 + 入队 + 弹悬浮确认框）
   ▼
BillPageParser（纯函数：金额 + 账单关键词 → 金额/店铺/商品/对象/交易时间/置信度）
   ▼
ScreenCaptureStore（待确认箱，≤30 条，保留 7 天，按页面签名去重）
   ▼  置信度 ≥ 0.5
悬浮确认框（TYPE_ACCESSIBILITY_OVERLAY，就在当前页面上：可改金额/店铺/商品 → 确认 / 忽略）
   ▼  确认
ScreenCaptureStore 标记 userConfirmed=true → 打开应用
   ▼
Flutter：已确认的直接落账；没确认的（或低置信度）走应用内 BillConfirmDialog
   ▼
落账：先查重 →
   ├─ 命中已有账目 → 只补全缺失的推测字段（金额/时间等事实字段不动）
   └─ 未命中       → 新增一笔（复用来源标签、类别体系）
```

> 说明：**Android 不允许应用自己打开无障碍开关**，所以「一键开启」只能是一键跳到本应用的无障碍设置页 + 引导，无法代你打开。

## 4. 关键实现点

| 主题 | 做法 |
| --- | --- |
| 触发 | 只处理 `TYPE_WINDOW_CONTENT_CHANGED / STATE_CHANGED`；至少间隔 700ms；单页最多读 800 个节点 |
| 特征门槛 | 必须**同时**有金额（`¥/￥/CNY/元` 或「金额」标签）与账单关键词，否则忽略 |
| 同页防抖 | 页面签名（包名 + 数字挖空文字 + 金额 + 交易时间分钟）短期重复即跳过 |
| 置信度 | 货币标记 + 账单词 + 商户 + 对象累加；≥0.5 才弹悬浮框，否则只留在待确认箱 |
| 交易时间 | 从页面读（`2026-10-12 12:34`、`10月12日 12:34`、`今天/昨天 12:34`）；读不到退化为识别时刻，并**分开记录**识别时刻用于保留期 |
| 店铺 / 商品 | 店铺=商户（商户/商家/店铺/卖家…）；商品=标签「商品/商品名称/宝贝」附近文字 |
| 悬浮确认框 | 无障碍服务用 `TYPE_ACCESSIBILITY_OVERLAY` 在当前页面上弹框（**无需额外权限**），可改金额/店铺/商品，确认或忽略 |
| 确认后 | 悬浮框确认 → 草稿标 `userConfirmed` → Flutter 直接落账（不再二次弹框）；忽略 → 从待确认箱删掉 |
| 去重 | 去账本里找"一样的"：金额一致 + **交易时间接近**（±5 分钟）+ 商户 / 对象 / 合并键吻合；同商户同金额但时间差得远 = 两次消费，不并 |
| 补全 | 只填空字段（商户/对象/备注/分类/资金来源）；**已有值一律不动**，尤其用户改过的分类 |
| 冲突优先级 | 同一笔字段 **通知 > 页面识别**：页面识别命中通知产生的账目时只补不改 |

## 5. 权限与隐私

- 需用户手动开启**无障碍服务**：设置页「自动记账处理情况」卡片里点「一键开启」→ 引导 → 跳系统设置。
- 悬浮确认框用 `TYPE_ACCESSIBILITY_OVERLAY`，**不需要** `SYSTEM_ALERT_WINDOW`（悬浮窗）权限。
- 服务只读窗口文字，**不模拟点击、不输入、不联网、不调用模型**。
- 只处理「像账单」的页面：同时命中金额与账单关键词才入队；其余页面（聊天、验证码、广告）直接忽略。
- 识别草稿存应用私有目录，上限 30 条、保留 7 天。

## 6. 已知限制（如实列出）

| 限制 | 说明 |
| --- | --- |
| WebView / 自绘页面读不到节点 | 这类页面（部分 H5、Flutter、Canvas）会识别失败，请手动记一笔；v1 不引入 OCR |
| 字段归因靠启发式 | 页面没有固定格式，字段与交易时间靠标签/相邻节点/时间正则推断，可能误读 —— 所以确认框里可改 |
| 商品名多无标签 | 淘宝等页面商品名常是一整块无标签文字，靠标签提取可能取不到，需在悬浮框里手动补 |
| 交易时间格式不一 | 只覆盖常见写法（含年月日、月日、今天/昨天）；显示「几秒前」等相对时间或格式特殊时读不到，退化为识别时刻，判重会偏保守 |
| 只做单笔详情页 | 不做列表页一屏多笔 |
| 通用识别有误报可能 | 用「金额 + 账单关键词」门槛 + 置信度阈值 + 确认框共同压制 |
